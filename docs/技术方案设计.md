## 1. 技术选型总览

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | React + TypeScript + Vite + Ant Design | SPA 单页应用 |
| 后端 | Python + FastAPI | 异步 Web 框架，自带 OpenAPI 文档 |
| 数据库 | MySQL 8.0 | 关系型数据库 |
| ORM | SQLAlchemy 2.0（异步） | 配合 FastAPI 异步生态 |
| 迁移 | Alembic | 数据库结构版本管理 |
| 认证 | JWT | 无状态令牌认证 |
| 附件存储 | 本地磁盘 | 服务器本地目录 |
| 缓存/任务 | 可选引入 Redis + Celery（后期） | 本期先不引入，用定时任务替代 |
| 部署 | 手动部署 | 进程 + Nginx 反向代理 |

## 2. 系统架构

### 2.1 总体架构

```
┌─────────────────────────────────────────────┐
│                浏览器（React SPA）            │
└──────────────────┬──────────────────────────┘
                   │ HTTPS / HTTP
                   ▼
┌─────────────────────────────────────────────┐
│              Nginx（反向代理 / 静态资源）       │
│        ├─ /            → 前端静态文件          │
│        └─ /api/*       → 后端 FastAPI        │
└──────────────────┬──────────────────────────┘
                   ▼
┌─────────────────────────────────────────────┐
│           FastAPI 后端（Python）              │
│   ├─ 认证鉴权（JWT）                          │
│   ├─ 业务模块（档案/分类/用户/日志/提醒/导入导出）│
│   └─ 定时任务（到期提醒扫描）                    │
└───────┬──────────────────────────┬───────────┘
        │                          │
        ▼                          ▼
┌───────────────┐          ┌──────────────────┐
│  MySQL 8.0    │          │  本地磁盘存储      │
│  （业务数据）  │          │  （证书附件）      │
└───────────────┘          └──────────────────┘
```

### 2.2 分层结构（后端）

```
router（接口层） → service（业务层） → model（数据访问层）
                      ↓
                   schema（Pydantic 校验）
```

## 6. 关键设计点

### 6.1 认证与鉴权

- 登录成功签发 JWT，token 携带 `user_id` 与 `role`。
- 后端通过依赖注入解析 token，校验用户状态与角色。
- 普通用户访问档案接口时，强制 `user_id = 当前用户`，实现数据隔离。
- 管理员访问档案接口时，可传 `user_id` 过滤查看任意用户。

### 6.2 附件存储

- 存储根目录：`backend/storage/`，按 `{user_id}/{archive_id}/{uuid}.{ext}` 组织。
- 上传时校验扩展名（jpg/jpeg/png/pdf）与大小（默认 20MB，可在配置调整）。
- 附件下载接口校验权限（仅本人或管理员可访问）。
- 图片在线预览、PDF 通过浏览器内嵌预览。

### 6.3 到期提醒

- 通过 FastAPI 的定时任务（APScheduler）每日扫描 `expire_date` 字段。
- 规则：距离到期 ≤ 提前天数（默认 30 天，可配置）→ 即将到期；已过有效期 → 已过期。
- 首页与「即将到期/已过期」列表实时计算，无需持久化提醒记录。

### 6.4 导入导出

- 导出：使用 `openpyxl`/`pandas` 生成 Excel，导出当前筛选结果。
- 导入：提供模板下载，解析 Excel，逐行校验（必填、格式、分类存在性），返回错误行提示。
- 导入为批量新增，成功后写操作日志。

### 6.5 操作日志

- 通过中间件/装饰器统一记录关键操作（增删改、导入导出、登录）。
- 记录：操作人、动作、对象类型、对象 ID、详情（JSON 快照）、IP、时间。

### 6.6 软删除

- 档案采用软删除（`deleted_at` 标记），保留数据可追溯，列表默认过滤已删除。

## 8. 部署方案（手动部署）

### 8.1 环境准备

- 服务器：Linux（Ubuntu/CentOS 均可）
- 依赖：Python 3.11+、Node.js 20+、MySQL 8.0、Nginx

### 8.2 部署步骤

1. **数据库**：创建库 `e_archives_system`，运行 Alembic 迁移建表，初始化默认分类与管理员账号。
2. **后端**：`pip install -r requirements.txt`，配置 `.env`，用 `uvicorn` 启动（配合 systemd 守护）。
3. **前端**：`npm run build` 产出静态文件。
4. **Nginx**：托管前端静态文件，`/api` 反向代理到后端端口（如 `127.0.0.1:8000`）。
5. **定时任务**：APScheduler 随后端进程运行，或独立 systemd 定时触发。

### 8.3 systemd 配置示例（后端）

```ini
[Unit]
Description=e-ArchivesSystem backend
After=network.target

[Service]
WorkingDirectory=/opt/e-archives-system/backend
ExecStart=/opt/e-archives-system/backend/venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=always

[Install]
WantedBy=multi-user.target
```

### 8.4 Nginx 配置示例

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    root /opt/e-archives-system/frontend/dist;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端接口
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 20m;
    }
}
```

## 9. 安全设计

- 密码使用 bcrypt 哈希存储，不存明文。
- JWT 设置过期时间（如 24h），支持刷新。
- 接口统一鉴权中间件，越权访问拦截。
- 附件访问做权限校验，禁止直接暴露存储目录。
- 上传文件做类型白名单与大小限制，防止恶意文件。
- 接口参数校验（Pydantic），防止 SQL 注入（ORM 参数化）。
